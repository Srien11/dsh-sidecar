# dsh-sidecar 产品规格

## 一句话定义

从 DeepSeek Harness 任意已完成回答打开一个持久化侧边追问抽屉，不跳离、不改写、不打断主对话。

## 目标用户

- 阅读长回答时需要解释术语、验证细节或要求举例的用户。
- 希望探索旁支问题，又不想让旁支内容污染主对话上下文的用户。
- 需要稍后回到追问结果，同时保留主线阅读位置的用户。

## 核心任务流

1. 用户悬停一条已完成的 Assistant 回答。
2. 用户点击“侧边追问”。
3. 插件从该回答所属的已完成轮次创建或选择一个 child Session。
4. 右侧抽屉打开，主对话仍保持原来的内容和滚动位置。
5. 用户在抽屉中继续追问；每轮由 Harness 正常持久化。
6. 用户关闭抽屉；关闭不删除 Session。
7. 原回答显示追问数量，用户之后可重新打开任一分支。
8. 用户可选择、新建、重命名或归档分支；任何内容都不会自动注入主对话。

## MVP 范围

### 必须有

- 仅在可安全 fork 的已完成 Assistant 回答上显示入口。
- 单个右侧抽屉。
- 每个锚点支持多个持久分支。
- 创建、打开、关闭、重命名和归档分支。
- 恢复主对话滚动位置和输入草稿。
- 中文与英文界面。
- 键盘操作、焦点管理和屏幕阅读器标签。
- 明确提示对话隔离不等于工具副作用隔离。
- 持久锚点的存储、RPC 与恢复测试。

### 明确不做

- 编辑或重写历史消息。
- 自动把分支合并回主对话。
- 文件系统回退、Git 合并或 worktree 管理。
- 通用 Session 版本树。
- 同时打开多个抽屉。
- 移动端专属布局。

## 行为不变量

- 创建分支不会修改父 Session 的事件日志。
- 抽屉关闭不会删除、归档或截断子 Session。
- sidecar 中的提示词只发送给 sidecar Session。
- 主对话输入草稿不得被 sidecar 输入覆盖。
- 分支锚点必须落在已完成轮次边界。
- 任何失败都不得静默创建重复分支。
- 卸载插件后，已创建的 child Session 仍是 Harness 可读取的普通 Session。

## 工具副作用边界

当前 Harness `0.1.0-rc.6` 没有向插件公开逐 Session 的 preset/filter 接口，因此本 Beta 只保证对话记录隔离，不承诺工具副作用隔离。README 必须持续明确这一边界；如果后续官方公开逐 Session 能力过滤，再单独设计默认只读模式。

## 成功指标

- 从点击入口到抽屉可输入的中位时间小于 500ms（不含首次模型响应）。
- 关闭再打开后，分支内容恢复成功率 100%。
- 创建或使用 sidecar 后，父 Session 事件数量保持不变。
- 单元与轻量集成测试覆盖持久恢复、失败重试、多分支和归档边界。
- 发布前在资源可控的隔离环境完成刷新、重启与浏览器端到端验收。
- 安装后无需手工编辑 `cordis.yml`。
